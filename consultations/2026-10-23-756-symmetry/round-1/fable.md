## Summary

**The symmetry route is closed for this code: the automorphism group of its Tanner graph is exactly the 378 translations the search already uses. I computed this; the argument and code are below. The ~1000× needed to reach bound 29 cannot come from symmetry.** What can plausibly give it is a stronger admissible pruning bound inside the same search (the exactness argument survives unchanged), which I describe and give a testable prediction for.

## 1. The automorphism group (computed; the two parts are each machine-checkable)

**Setup.** Tanner graph on 1512 vertices: 756 qubits, 378 X-checks (rows of H_X), 378 Z-checks (rows of H_Z), with the three classes coloured. An automorphism preserving the classes permutes qubits so that H_X's row set and H_Z's row set are each preserved, hence ker H_X and rowspace H_Z are preserved.

**Claim 1a (computed, proved by the computation): the stabilizer of qubit 0 in Aut is trivial.** I individualized qubit 0 (gave it a fourth colour) and ran colour refinement (1‑WL: a vertex's new colour = its old colour + multiset of neighbours' colours, iterated to a fixed point). The result is discrete: 1512 cells of 1512. Refinement is automorphism-invariant, so any automorphism fixing qubit 0 fixes every cell, i.e. is the identity.

**Claim 1b (computed): the orbit of qubit 0 is exactly the 378 left-block qubits.** For each target qubit t, I individualized t, refined, and (when the colour multiset matched) built the unique colour-matching bijection and verified edge by edge that it is a graph automorphism. 378 targets passed (all in the left block, none in the right). So **|Aut| = 378**, and it is the translation group {T_g}. Generators: T_x: (blk, i, j) → (blk, i+1 mod 21, j) and T_y: (blk, i, j) → (blk, i, j+1 mod 18), on index blk·378 + i·18 + j.

**Claim 1c (computed, subsumed by 1a/1b but independently checked):** among all 648 automorphisms σ of Z_21×Z_18 (x→x^a y^b, y→x^c y^d with b∈{0,6,12}, c∈{0,7,14}), combined with any monomial shift and optionally the block swap, the only one with {g·σ(A), g·σ(B)} = {A, B} (resp. swapped) is the identity. In particular inversion+swap (Φ) does *not* preserve Z-logicals: it maps them to X-logicals (A* and B* are not shifts of A, B), which is the d_X = d_Z argument and nothing more.

**Caveat (not computed).** A permutation could preserve ker H_X and rowspace H_Z without preserving the row sets. That cannot happen if the weight-6 words of rowspace(H_X) are exactly its 378 rows (then any such permutation permutes the rows, hence is a Tanner automorphism; the same for H_Z). Two distinct rows A·g, B·g pairs overlap in at most one position per block (the differences of A's exponents are all distinct), so sums of two rows weigh ≥ 8; a weight-6 word would need ≥ 3 rows. **Registered prediction P1:** the minimum weight of rowspace(H_X) is 6, attained only by the 378 rows; the search with bound 7 on the "code" rowspace(H_X) (anchors 0 and lm, labels = "is not a single row") finds nothing. If P1 holds, the full group preserving the Z-logicals is the translations, and the search's anchor reduction is already optimal.

## 2. Using symmetry in the search

With G = translations only, the only residual redundancy is that a logical with w_L left-block qubits is reached w_L times (once per translate putting a left qubit at 0; w_L ≈ w/2 ≈ 12–17). Canonical-augmentation pruning (require 0 to be the lexicographically least translate) is hard to enforce early in a check-driven search since S is not built in lex order; a cheap sound partial version is: whenever S contains a left qubit q ≠ 0 whose translate by −q would make the set (S−q) contain a qubit below 0 — impossible, so nothing prunes until S is complete. Realistic gain ≤ w_L ≈ 10× in the leaf count and much less in nodes; **I estimate 2–5×, not the 1000× needed** (conjecture). Do not invest here.

## 3. Routes that can reach 26 or 30

**3a. Stronger admissible pruning (recommended; same exactness proof).** The current cut is |S| + ⌈u/maxcol⌉ ≥ best with maxcol = 3. The soundness argument only needs "a valid lower bound on the number of further qubits needed to clear the syndrome, over qubits > anchor, not excluded". Two stronger ones, both integer-only:
- *Packing bound:* greedily pick unsatisfied checks whose candidate sets are pairwise disjoint; each needs its own new qubit, so ≥ |packing| more qubits. Combine with max(|packing|, ⌈u/3⌉).
- *Parity/neighbourhood bound:* an unsatisfied check with exactly one candidate forces that qubit (unit propagation — add it, don't branch); with zero candidates, cut (already done). Forced qubits chained this way shrink the tree a lot near the bottom of deep passes.
Both are sound by the same "some branch stays inside c" argument: c's remaining qubits clear all unsatisfied checks, so any lower bound on the size of a set of candidates clearing them is ≤ w − |S|. **Prediction P2 (conjecture, testable on the development codes against enumeration and against the current node counts): packing + unit propagation reduces nodes per pass by ≥ 10× at bounds 22–24 on this code, moving the ~10×/2 bounds growth to reach bound 27 (d ≥ 28) within days on 4 cores.** Reaching 29 is uncertain.

**3b. Meet-in-the-middle on the syndrome (recommended second).** Split the qubits (per anchor) into the ones found by the check-driven search up to depth ⌈w/2⌉ and a hash table of syndromes of small sets; a Z-logical of weight w is the union of two half-sets with equal H_X-syndrome. This is the standard way exact distance computations reach d ≈ 30 on n ≈ 700 (memory ~ number of half-sets), and it is exact by construction; its correctness is simple to state (every weight-w kernel vector is a pair of equal-syndrome halves) and checkable against enumeration. Cost estimate (conjecture): with translations, ~C(378,·)-sized half enumerations are too big naively, so it must be combined with the check-driven generation of *connected* halves; I expect 26 within days, 30 uncertain.

**3c. Quotient torus (not sound as stated; a caveat for the project).** The ring map π: y ↦ y mod 6 (summing over the three fibres) sends ker H_X into the kernel of the quotient code (A, B mod y^6−1) and does not raise weight. But π(c) may be 0 or a quotient stabilizer for a logical c, so d_quotient is *not* a lower bound on d without a separate argument covering that case (e.g. c is then a sum of fibre-parity-even pieces, which needs its own bound). Treat as a case split, not a bound, until that case is handled.

**3d. LP/SDP bounds** (Delsarte-type for quantum codes) are far too weak at n = 756, k = 16 (they give d ≲ 200 upper bounds, no useful lower bound). **Brouwer–Zimmermann** gives lower bounds on the minimum weight of a linear code; for CSS one needs the coset version (minimum weight of ker H_X outside rowspace H_Z), which exists (Zimmermann-style on the 394-dimensional code ker H_X with the 378-dimensional subcode excluded) and is probably how the secondhand d ≥ 30 was obtained (conjecture — I have not seen that work). It is exact and its soundness is a textbook argument (information-set enumeration up to weight t certifies d ≥ sum over sets of max(0, t+1−redundancy)), checkable against enumeration on small codes. **Prediction P3 (conjecture):** with 16 information sets, enumeration to weight 5–6 per set (about 10^11 codewords) certifies d ≥ 30 within days on 4 cores. This is the route I would register first for 30.

## Where I think the project is wrong or missing something
- The hope in Q1/Q2 (speedup ≈ |G|/lm) assumed G ⊋ translations; it is not (Claims 1a–1b). Symmetry is a dead end for this code.
- The pruning bound ⌈u/3⌉ is the weakest admissible one; most of the 1000× is likely recoverable there (P2), with no change to the correctness argument.
- The quotient-torus idea in Q3 needs the π(c) ∈ {0} ∪ stabilizers case handled before it is a bound.
