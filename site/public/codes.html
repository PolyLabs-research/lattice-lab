Quantum codes

Every linear result on this site is about one object: polynomials in x and y over GF(2), on a torus. A pair of them is a bivariate bicycle code, the family of IBM's [[144,12,12]] gross code. A registered test found that the instruments built for periods count these codes' logical qubits: they agreed with plain linear algebra on 3,000 of 3,000 random codes and reproduced all 12 published values. A second registered test then computed their distances, which decide whether a code is any use, and reproduced all 12 of those too.

One object, two uses

A linear rule on the l × m torus is a polynomial in x and y, taken mod xl − 1 and ym − 1. Each monomial xpyq is a translation, and the rule adds, mod 2, the cells its translations reach. These polynomials form a ring, the group ring of the torus.

On an odd torus a rule acts diagonally. Its eigenvalues are its values at the torus's characters, in a finite field F(2d). The orders of the nonzero eigenvalues set the rule's period, as the linear atlas shows. A quantum code's logical qubits are set by the zero eigenvalues: the characters a rule wipes out.

What a quantum code is

Qubits are noisy. A quantum error-correcting code spreads k logical qubits over n physical ones, and measures parity checks. Each check reports the parity of a few qubits, which reveals errors without reading the information stored. There are two kinds of check, for the two kinds of error a qubit suffers: bit flips and phase flips.

A code is written [[n, k, d]]. Its distance d is the weight of its smallest logical error: the fewest qubits an error must touch to change the stored information while every check stays silent. An error on fewer than d qubits is either caught by a check or does no harm.

Two rules make the gross code

A bivariate bicycle code (Bravyi et al., 2024) takes two polynomials A and B on the l × m torus, and two copies of the torus, left and right, with a qubit on every cell: n = 2lm. Its checks are HX = [A | B] and HZ = [BT | AT]. The X check at cell (i, j) reads, on the left copy, the cells (i − p, j − q) for each monomial xpyq of A, and on the right the same for B. The Z check reads (i + p, j + q): B's monomials on the left, and A's on the right.

IBM's gross code is A = x3 + y + y2 and B = y3 + x + x2 on the 12 × 6 torus, so n = 144.

Each check reads six qubits, three on each copy, and each qubit is read by three X checks and three Z checks. The checks are sparse, and local on the torus. The arrow keys move the check too.

Logical qubits from the characters

The number of logical qubits is k = n − rank HX − rank HZ = 2 dim(ker A ∩ ker B): twice the number of independent patterns that A and B both wipe out.

That count can be read off the characters. The ring is a Frobenius algebra, so dim(ker A ∩ ker B) = dim R/(A, B), and R splits over the characters of the torus's odd part. At odd sizes, k is twice the number of characters where A and B both vanish: zero eigenvalues, which this project's instruments already compute.

At even sizes, write l = 2al′ and m = 2bm′ with l′ and m′ odd. Each common zero on the l′ × m′ odd part then counts with its multiplicity in the 2-part: the same split of a torus into odd part and 2-part as the library's even-size reduction.

Each square is one character χ = (u, v) of the odd part: row u for x, column v for y. Write A and B as sums of monomials, such as x^3 + y + y^2, or 1 + π + π^2 with π = xy; 0 is the zero polynomial. Exponents are taken mod l and m, and a repeated monomial cancels, as it does mod 2. Your browser computes the ranks over GF(2), and the characters in the same field F(2d) as the project's code, so the squares carry the labels of its records. What the characters show

The [[72,12,6]], [[144,12,12]] and [[288,12,18]] codes share k = 12 because the same four characters of their 3 × 3 odd part carry it, two of them with multiplicity 2 in the 2-part. The coprime codes each take k from one Frobenius orbit of common zeros, so k is twice the orbit's size: the orbit {1, 2, 4} mod 7 for [[42,6,6]], and an orbit of six characters of the 7 × 9 torus for [[126,12,10]]. Symmetries: equivalent codes, and cheap gates

A map of the torus sends a code to an equivalent code: the same code with its qubits relabelled. The image test that shrank this project's censuses, by maps in GL2(Z/m), is a code-equivalence test, and it can shrink a search for codes the same way.

A symmetry of the torus that maps a code to itself is an automorphism of the code. Automorphisms are being studied as fault-tolerant logical gates, done by permuting qubits. The fourth pilot's half-Frobenius mechanism is exactly invariance under a dilation (x, y) → (xc, yc), by c = 6 at m = 37. Neither use has been tried on codes yet.

The path

  1. Rediscovery. Done: the registered tests above reproduced every published k and every published distance.
  2. A census of code families. Sweep polynomial pairs at many sizes for high k, using the classes and symmetries to prune. Then measure distance, the hard and expensive part: the exhaustive search for exact values, the integer program as a cross-check and for bounds, randomised information-set methods for larger codes, and circuit-noise simulation (stim, BP-OSD decoders) for the logical error rates practitioners care about. This is where the compute goes. Stage 1 is done, as an exploratory survey: every code of the published form on 116 tori up to 200 qubits, 3,330 distinct classes with an exact distance each, and some sizes held back untouched. The gross code has the best ratio k d²/n of all of them, and an exact rule, proved by hand, says which tori have codes at all. A registered test of predictions on the held-back sizes comes next.
  3. Pilots on codes. Point the agent loop at structural questions with a payoff for codes. For example: which conditions on (A, B) force many logical qubits and a torus automorphism at once? The judge checks k exactly and distance independently, on held-out sizes registered in advance, as in the seven pilots so far.
  4. Certificates. Extend the Lean bridge to k and to automorphisms. Distance will mostly stay outside Lean, but a certified k and certified symmetries with independently checked distances are a stronger claim than most code-search papers make.

The plan names two weaker leads for the same algebra. Linear cellular automata are standard test-pattern generators in chip testing, where a short cycle is a defect, and the mechanisms here predict exactly when the cycle collapses. In fracton and fractal spin models (Newman–Moore is built on the triangle rule), ground-state counts and recurrence times are given by the same algebra. The codes are the strongest of the three: a live field, an industrial roadmap built on exactly this ring, and a quantity, k, that the instruments here already compute.

Caveats

Distance. Distance decides whether a code is useful. The project now computes it exactly for codes like the published ones, with two instruments that were fixed after a registered test caught a solver fault, and then passed a second registered test. Distance says nothing about how a code does under realistic noise, which needs simulation.

Competition. Bivariate bicycle code search is active, with groups searching by brute force, by covering-graph constructions, and already with LLM-guided search. What this project would bring is its method (machine-checked structure, and held-out tests registered in advance) and any new families it finds, not a head start.

Sources. The published codes were transcribed from search summaries of the papers, because arXiv was not reachable from the environment the work runs in, and are still to be checked against the papers. A disagreement with a published k would first be a question about the transcription.
